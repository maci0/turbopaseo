# opencode-sdk

`@opencode-ai/sdk/v2/client` in the native daemon, selected by the `paths` entry in
`native/entries/daemon/tsconfig.template.json`. Node keeps the real SDK.

The SDK's client is generated by hey-api: every request is assembled at run time from
parameter tables and object spreads, and `gen/client.gen.js` constructs a default client at
module load. scriptc cannot compile that (`SC1101`: function values with async generator
results passed through untyped slots), so the daemon stopped at startup. `client.ts`
implements the 23 calls Paseo makes and the `global.event` stream with the generated
client's request and response rules (listed at the top of the file). Types are the SDK's
own `types.gen.d.ts`, copied into `types/` by `sync-types.sh` (gitignored; `make daemon`
and `test.sh` run it).

## Verified

`./test.sh` runs `tests/scenario.ts` through the real SDK (under Bun) and through
`client.ts` (a native scriptc build), both against `tests/fake-server.ts`, and compares the
outputs: 28 of 28 identical. That covers every endpoint Paseo calls, a JSON error body, a
text error body, a 204, a `text/html` response (throws), a fetch failure, the GET rewrite of
`x-opencode-directory` into the `directory` query parameter (with URL form encoding), and
the event stream (`id:`, `retry:`, multi-line `data:`, CRLF framing). Paseo's OpenCode
provider tests pass under Node with the real SDK.

## Differences from the SDK

- Results are one record `{ data, error, request, response }`, not the SDK's
  `{ data } | { error }` union (scriptc cannot tell the arms apart), and `error` is typed
  `unknown`. Exactly one of `data` and `error` is set, as before.
- JSON bodies list fields in the stand-in's order, not the caller's (same JSON value).
- A native build checks each response against the SDK's declared type. A response that
  does not match, an empty body on an endpoint that declares one, or a non-JSON event
  throws a TypeError natively, where the SDK passes the value through.
- Only `baseUrl`, `directory` and `fetch` are read from the config; no other SDK option
  (`throwOnError`, `responseStyle`, interceptors) is implemented.

## Not verified

Against a real OpenCode server: running one is outside what this project's tests may do.
